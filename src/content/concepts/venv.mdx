---
title: venv
summary: venv 为项目创建隔离环境，让依赖和解释器版本不互相污染。
whyImportant: 不同项目常需要不同版本的库。虚拟环境能把依赖限制在项目内，让安装、运行和部署更可控。
definition: venv 是标准库里的虚拟环境模块，用来创建独立解释器和包目录。
mentalModel: venv 像给每个项目一个独立工具箱，不同项目可以装不同版本的工具。

codeExamples:
  - title: naive
    description: 不创建虚拟环境就直接安装依赖，多个项目会共用同一套包。
    runnable: false
    code: |
      python -m pip install requests
      python project_a.py
      python project_b.py
  - title: standard
    description: 每个项目创建自己的 .venv，再在这个环境里安装依赖。
    runnable: false
    code: |
      python -m venv .venv
      .venv\Scripts\python -m pip install requests
      .venv\Scripts\python app.py
  - title: production
    description: 工程版把环境创建、pip 升级和依赖安装固定成可重复流程。
    runnable: false
    code: |
      python -m venv .venv
      .venv\Scripts\python -m pip install --upgrade pip
      .venv\Scripts\python -m pip install -r requirements.txt
      .venv\Scripts\python -m pip check
---
venv 解决的是“这个项目到底用哪一套依赖”。它是 Web、数据和 AI 工程里最早应该建立的工程卫生习惯。
