## 概念定义

Python 的多范式不是让代码随意混搭，而是给不同问题保留不同表达方式。一次性脚本适合过程式，清洗管道适合函数和推导式，长期维护的数据实体适合 class 或 dataclass。

新人可以先用一个判断：如果只是一次流程，先写清楚步骤；如果一段逻辑会被复用，抽成函数；如果同一组数据和行为总是一起移动，再考虑类。

## 真实案例

命令行通讯录可以先用字典和函数写出来，等联系人字段、校验和显示逻辑开始稳定，再把它们收成 dataclass。这个转变比从第一天就背 OOP 概念更自然。

## 历史脉络

Python 的实用主义让它长期容纳多种风格。这个节点也连接到 PEP 20 里的“实用胜于纯粹”：写法的优先级不是范式标签，而是清晰、可维护和适合问题。
